Install

$ npm i framebudget

npm i framebudget installs the core, framework-free, for any site. ESM only, with type declarations and one dependency: it re-exports @framebudget/core, the same code.

React, Vue and Angular each have their own package, which installs @framebudget/core for you and lists its framework as a peer dependency: npm i @framebudget/react, npm i @framebudget/vue or npm i @framebudget/angular. Installing only the binding is fine. With framebudget next to a binding, both resolve to the same @framebudget/core, so the page still has one budget.

Boot script

Inline it as the first script in <head>, before your CSS. It runs the cold benchmark (about 1.6 ms of work), decides, and writes the result on <html> before the first paint. It is self-contained (3.7 KB gzipped), never throws, and works when any browser API is missing.

import { bootScript, createBootScript } from "framebudget/boot";

// Default options:
const head = `<script>${bootScript}</script>`;

// With the calibration you pass to configure(), so boot and core agree:
const custom = createBootScript({ calibrationDefaults: { effects: { confetti: { threshold: 60, cost: 4, motion: true } } } });

CSS can then gate effects without any JavaScript:

html[data-framebudget-effects~="parallax"] .hero { transform: translateY(var(--parallax)); }
html[data-framebudget-effects~="blur"] .sheet { backdrop-filter: blur(16px); }

With a Content Security Policy, add a nonce or the script's hash.

The budget

The core starts on the first call to any method. It adopts the boot script's decision, runs a longer warm benchmark at the load event, then starts the governor. On the server, allows() answers false and the tier is Lite.

MemberDescription
budget.allows(effect)May this effect run on this device? Unknown effects answer false.
budget.tierThe current tier: "Full", "High", "Medium" or "Lite".
budget.scoreThe score after hardware caps and pressure, or null on the server.
budget.effects()The allowed effects.
budget.snapshot()Everything: scores, kernel rates, hints, the reason each effect is off, fps per source, the calibration.
budget.on("change", fn)Calls fn(snapshot, reason) and returns the unsubscribe function.
budget.off("change", fn)Unsubscribes.
budget.reportFrame(gapMs, source?)Reports the time between two frames, for the governor.
budget.register(name, definition)Adds an effect, or replaces one.
budget.configure(options)Calibration (calibrationDefaults, calibration), governor and sharing options. Call it before the load event. Also exported as configure.
budget.force(tier | "auto")Forces a tier for the session.
budget.simulate(score | null)Debug and demo only: replaces the measured score for the session.
createBudget(options?)A separate instance, for tests or embedded widgets.
 
import { budget } from "framebudget";

if (budget.allows("parallax")) startParallax();

budget.on("change", (snapshot, reason) => {
  update(snapshot.effects);
});

Effects

Each effect has a score threshold, a relative frame cost, and optional flags. motion effects turn off under prefers-reduced-motion: reduce; data effects turn off under Save-Data or a 2g connection. These are the library's built-in effects with their default thresholds; this site registers its own, and the home page shows the values in force on your device:

Register your own, and pass the same definitions to createBootScript so the first paint already knows them:

budget.register("confetti", { threshold: 60, cost: 4, motion: true });

Hysteresis. An effect that was on stays on down to threshold * (1 - hysteresis), and an effect that was off turns on only from threshold * (1 + hysteresis). The default margin is 10%, and the previous state is kept across pages.

Tiers

A tier's set is every effect whose threshold is at or below the tier floor. The reported tier is the highest tier whose whole set is allowed. Effects off because of a user preference do not lower the tier; thresholds, learning and the governor do.

TierDefault floorBuilt-in effects
Lite20hover
Medium35adds canvasLowRes, entrances
High70adds shimmer, sound, pageTransition, parallax
Full120adds blur, canvasHiRes

Simulating a device

budget.simulate(score) replaces the measured score for the session, and budget.simulate(null) returns to the real device. The boot script and the core both read the session value, so the next page's first paint already uses it. Try it: the device you picked on the home page is still active here, and the dock at the bottom takes you back.

The simulated score goes through the normal path: thresholds with hysteresis, hardware caps, pressure, reduced motion and the governor. While simulating, nothing is written about the real device and no telemetry is sent. snapshot().simulated holds the score. This API is for debugging and demos, not for product decisions.

budget.simulate(35);   // a budget phone from 2019
budget.simulate(null); // back to the real device

Governor

The governor starts at load. Frames reported with budget.reportFrame before load are queued (up to 1000) and handed to it at load, not dropped. It groups frames in windows of 30 per source. A frame is late when it takes more than 1.5 frame times (the display's own cadence, never faster than targetFps, default 60); a window is bad when more than 10% of its frames are late (maxLateFraction) or it runs under 30 fps (minFps). After 3 bad windows in a row from one source it steps one effect down, waits a 2 s cooldown, and emits change.

  • The 3 s warm-up after load (warmupMs) applies only to "main" and "worker" frames. An effect's own frames are judged from its first frame, before load included. The cooldown after a change applies to every source.
  • Consecutive frames of one effect form a run, which ends when the effect stops reporting for maxGapMs (1 s) or the page is hidden. A run that lasted at least minRunMs (250 ms) and averaged under minFps steps that effect down for good, and local learning remembers it, so the next visits start without it. Short effects such as page transitions and draw-ins are caught this way; long-running effects are still judged in windows too.
  • Frames reported as "main" or "worker" step down the most expensive allowed effect.
  • Frames reported with an effect's name step down that effect: report a canvas loop as budget.reportFrame(gap, "canvasHiRes").
  • framebudget samples main-thread frames itself during the first seconds and while the visitor interacts. Turn that off with configure({ governor: { auto: false } }).
// worker
postMessage({ type: "frame", gap });
// page
worker.addEventListener("message", (e) => {
  if (e.data.type === "frame") budget.reportFrame(e.data.gap, "worker");
});

Tune targetFps, minFps, maxLateFraction, windowFrames, strikes, warmupMs, cooldownMs, cleanWindows, maxGapMs and minRunMs with configure({ governor }).

Local learning

Always on, and it stays on the device: one guarded localStorage entry per origin. When the governor steps an effect down, the next visits start without it. After 5 clean visits it is tried again; if it holds up it is forgotten, and if it stutters again the wait doubles. The cached warm score and the last qualified effects live in the same entry.

Calibration

Every number that turns measurements into decisions lives in defaultCalibration: reference rates, effect thresholds and costs, tier floors, hysteresis, hardware caps, pressure factors, the fallback score, the maximum age of a cached score and the clean visits before a retry. Precedence: built-in numbers, then your calibrationDefaults, then the calibration fetched while sharing is on (from framebudget.dev, or from your calibrationUrl), then your calibration overrides. Every value is validated. Ship the values the fetched calibration may refine as defaults, and pin with calibration only what must hold.

configure({
  calibrationDefaults: {
    effects: { parallax: { threshold: 80 } }, // refined by calibrationUrl
  },
  calibration: {
    tiers: { High: 80 },
    hysteresis: 0.15,
  },
});

Telemetry

Off by default. Only the site developer can turn it on. Once on, sampled reports always go to framebudget.dev, where they calibrate framebudget on real devices, from any site; that destination cannot be changed or removed. alsoSendTo adds one endpoint of your own, which gets the same report.

configure({ share: true }); // on, with the defaults below

configure({
  share: {
    sampleRate: 0.1, // share of page views that report (default 0.1)
    minIntervalDays: 7, // days a browser waits before reporting again (default 7)
    alsoSendTo: "https://example.com/framebudget", // optional: one extra endpoint, same report
    calibrationUrl: "https://example.com/calibration.json", // optional: replaces framebudget.dev's calibration
  },
});

configure({ share: null }); // or false: off, also after load
  • Where: https://framebudget.dev/api/report, always, plus alsoSendTo when set. The calibration comes from https://framebudget.dev/api/calibration unless calibrationUrl points elsewhere. Both framebudget.dev endpoints accept any origin.
  • Sent: calibration version, rounded scores, kernel rates, clock resolution, cores, memory, pressure, the reduced-motion preference, the tier, allowed and stepped-down effects, median fps per source.
  • Never sent: identifiers, cookies, the URL, the user agent, timestamps.
  • When: one navigator.sendBeacon call per destination when the page is hidden, after load, for sampled page views only.
  • How often: at most one report per browser every minIntervalDays days (default 7, 0 turns it off), sooner only for a new calibration version. The date of the last report stays in the same localStorage entry. The calibration is fetched at most once a day, after load, without credentials, and applied from the next visit.
  • Never under Global Privacy Control or Save-Data, while a tier is forced, or while a device is simulated.
  • Letting visitors say no: configure({ share: null }) turns sharing off at any time, also after load. Keep the visitor's choice yourself and pass share: null on later visits.
  • The beacon still carries what every request carries, such as the IP address and the Origin header. framebudget.dev keeps only coarse facts derived from the request (engine and major version, OS family, mobile or desktop, country, the day in UTC) and stores neither the IP address, the user agent string nor the Origin: see what it keeps.
  • Upgrading from 0.4: endpoint is now alsoSendTo, and it adds a destination instead of being the only one.

React

import { useBudget, useTier } from "@framebudget/react";

function Page() {
  const animate = useBudget("pageTransition"); // boolean, re-renders on change
  const tier = useTier();
  return animate ? <AnimatedRoute /> : <Route />;
}

During server rendering and hydration, useBudget answers false and useTier answers Lite, so effects only start on the client. BudgetProvider is only needed for a budget other than the page's.

Vue

<script setup lang="ts">
import { useBudget, useTier } from "@framebudget/vue";

const props = defineProps<{ effect: string }>();

const animate = useBudget(() => props.effect); // computed ref, follows the prop
const tier = useTier();
</script>

<template>
  <AnimatedRoute v-if="animate" :data-tier="tier" />
  <Route v-else />
</template>

useBudget returns a computed ref. The effect name may be a string, a ref or a getter such as a prop. useTier returns a computed ref of the tier. In a component both answer false and Lite until mount, so server rendering and hydration agree. provideBudget(budget), called in a parent's setup, is only needed for a budget other than the page's.

Angular

import { Component, input } from "@angular/core";
import { injectBudget, injectTier } from "@framebudget/angular";

@Component({
  selector: "app-route",
  template: `
    @if (animate()) {
      <app-animated-route [attr.data-tier]="tier()" />
    } @else {
      <app-plain-route />
    }
  `,
})
export class Route {
  readonly effect = input("pageTransition");
  readonly animate = injectBudget(this.effect); // Signal<boolean>
  readonly tier = injectTier();
}

Call injectBudget and injectTier in an injection context, such as a field initializer or the constructor. injectBudget returns a Signal<boolean>; the effect name may be a string or a signal such as an input. Both answer false and Lite until the first browser render. provideBudget(budget) returns a provider for the application, a route or a component, and is only needed for a budget other than the page's. The package has no decorators, so it needs no Angular compiler step.
